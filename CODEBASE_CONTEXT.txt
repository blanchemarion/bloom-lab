BLOOM LAB WEBSITE — CURRENT CODEBASE CONTEXT
============================================

Purpose
-------
This document describes the Bloom Lab website as currently implemented. It is
background context for developers and AI assistants working in this repository.
Inspect the relevant source before changing it: this is a guide, not a substitute
for the code, and it can become outdated as the site evolves.


1. PROJECT OVERVIEW
-------------------

This repository contains the public Bloom Lab website: https://bloom-lab.org

Bloom Lab is presented as an interdisciplinary community focused on biology,
life, computation, cognition, aging, and complexity. The application is a
client-rendered React site with a scroll-driven homepage, project articles, and
a small number of utility routes. There is no application backend and no
visitor data persistence.

Core technologies:

- React 18 and TypeScript
- Vite 5 with the SWC React plugin
- React Router 6
- Tailwind CSS 3 and shadcn/ui/Radix primitives
- Framer Motion 12
- Lucide React icons
- TanStack React Query (provided globally, but not central to current content)

The many generated components under src/components/ui are mostly shadcn/ui
scaffolding rather than the public site's primary implementation.


2. DEVELOPMENT, CONTENT SYNC, BUILD, AND DEPLOYMENT
---------------------------------------------------

Install and run locally:

  npm install
  npm run dev

Vite listens on port 8080 (host "::"). The @ alias resolves to src, and the
configured production base path is "/" for the custom root domain.

Useful scripts:

  npm run sync:posts   Fetch public Bloom Lab Substack posts into JSON
  npm run build        Refresh posts, then create a production build
  npm run build:dev    Development-mode Vite build (does not run prebuild)
  npm run lint
  npm run preview
  npm run deploy       Build and publish dist with gh-pages

The build script has an npm prebuild hook. scripts/sync-substack-posts.mjs calls
the Substack archive endpoint, keeps public posts, normalizes their fields, and
writes src/data/substack-posts.json. If the request fails but a cached JSON file
already exists, it warns and builds with the cache; without a cache it fails.

.github/workflows/deploy.yml also deploys to GitHub Pages on pushes to main (or
manual dispatch), using Node 20, npm install, npm run build, and the official
Pages artifact/deployment actions. Do not deploy or publish unless explicitly
asked.


3. APPLICATION ENTRY, PROVIDERS, AND ROUTES
-------------------------------------------

src/main.tsx mounts the application and imports src/index.css.

src/App.tsx wraps the route tree with React Query, the tooltip provider, both
toast systems, and BrowserRouter. RouterWithRedirect restores GitHub Pages deep
links from the ?redirect= query parameter, and ScrollToTop resets scroll on every
pathname change. Preserve both behaviors when editing routing.

Current routes:

  /                                  -> Index
  /main                              -> MainLanding directly
  /projects/biological-relativity    -> BiologicalRelativity
  /projects/soma                     -> Soma
  /projects/revamp                   -> ReVamp
  /projects/senereveal               -> SeneReveal
  /projects/3bodies                  -> Bodies
  /projects/coming-soon              -> ComingSoon
  all unknown paths                  -> NotFound

The root-level 404.html implements the GitHub Pages redirect handoff expected by
App.tsx. /main intentionally omits the Index-owned intro and floating navbar.


4. ROOT HOMEPAGE COMPOSITION AND ENTRY STATE
--------------------------------------------

src/pages/Index.tsx renders one continuous document:

  1. IntroPage
  2. Navbar (fixed overlay, outside normal layout flow)
  3. MainLanding

Index owns introRef and passes it to both IntroPage and Navbar so their motion is
synchronized to the same scroll target. On mount, Index forces the page to the
top with useLayoutEffect.

The centered Bloom logo is now a button. Activating it smoothly scrolls to 78%
of the intro's scrollable distance, the molecule reveal point. Index considers
the intro complete at that threshold. Once it has been reached by clicking or
normal scrolling, attempts to scroll above it are clamped back to the threshold
for the lifetime of that Index mount. This prevents returning to the initial
question/logo phase after entry. The clamp is recalculated on resize.

There is still no question input, submit form, cursor-following effect, wheel
event interception, or conditional replacement of IntroPage with MainLanding.
Before the completion threshold, scrolling uses normal browser behavior.


5. SCROLL-DRIVEN INTRODUCTION
-----------------------------

src/pages/IntroPage.tsx implements a 320vh section with a sticky 100vh viewport.
Framer Motion useScroll/useTransform scrub the sequence directly against the
section's scroll progress, with no timeline timer.

Current visual layers and behavior:

- Twelve philosophical questions occupy deterministic positions and drift with
  repeating animations. A central elliptical mask keeps the Bloom logo legible.
- A deterministic field of 74 depth-distributed blue dots covers the viewport.
- Questions and dots project away from a focal point, enlarge, blur, and fade at
  different rates to create depth during the zoom.
- The centered public/logo_bloom.png starts visible, then scales, blurs, and
  fades by progress 0.18. It is an accessible "Enter" button wired to Index.
- The focal public/image_molecule.png begins at 0.3vmin near the lower right and
  grows to FINAL_MOLECULE_SIZE (86vmin) by progress 0.78.
- Three decorative background copies of the molecule fade, sharpen, and shift
  into the surrounding field during the zoom.
- The final left-hand copy appears from progress 0.58 to 0.78 while the focal
  molecule fills the right side.
- Reduced-motion preference removes autonomous drift and most zoom/blur motion,
  while preserving the scroll-based visibility sequence.

Current revealed headline:

  "Because life is the universe’s most successful interdisciplinary project,
  we need to unite."

It is followed by a paragraph about scientific rigor, creativity, theoretical
frameworks, system-level biology, cognition, and biology as a language for
complexity. The headline uses Platypi; supporting typography uses Satoshi.


6. FLOATING NAVIGATION
----------------------

src/components/Navbar.tsx is a fixed, transparent, full-width header. It starts
hidden and non-interactive, then fades/slides into view between intro progress
0.78 and 0.84. aria-hidden and pointer-events follow availability. Reduced-motion
users keep the fade/availability logic without the vertical slide.

The leftmost control displays public/logo_blue.png and scrolls back to the 78%
molecule reveal point. Four text controls follow:

  Emerged Work  -> #emerged-work
  Schedule      -> #schedule
  Posts         -> #posts
  Team          -> #team

Controls use scrollIntoView; smooth behavior is replaced with automatic scroll
when reduced motion is requested. The row is horizontally scrollable on narrow
screens. About and Join Us are homepage section IDs but are not current navbar
items.


7. MAIN LANDING CONTENT
-----------------------

src/pages/MainLanding.tsx contains the content below the intro. It does not
render Navbar or NetworkScrollSection. Most blocks use a local AnimatedSection
wrapper built from Framer Motion and useInView, revealing once with optional
staggered children.

Sections in rendered order:

  1. About / three linked principles (id="about")
  2. Emerged Work project grid (id="emerged-work")
  3. Schedule (id="schedule")
  4. Posts (id="posts")
  5. A shared two-column Join Us and Team area
     - Join Us (id="join-us"; first visually on large screens)
     - Team (id="team")
  6. Footer

The About block links its three principles to Emerged Work, Schedule, and Posts.

Emerged Work uses public/background.png behind six cards:

- SeneReveal -> /projects/senereveal
- ReVamp -> /projects/revamp
- 3Bodies -> /projects/3bodies
- Soma -> /projects/soma
- BioResilience -> /projects/coming-soon
- Biological Relativity -> /projects/biological-relativity

Cards show a headline, year, and discipline chips using only the Bloom palette.

Schedule currently advertises a 2027 summit, "The World in 2100: What Left the
Lab," with details to be announced. Its past-events column links externally to
the Dec. 5–7, 2025 "Research Hackathon: Longevity x Intelligence" on Luma.

Posts imports src/data/substack-posts.json rather than hardcoding articles. It
shows the first three items initially, formats each publish date in English, and
offers Show more/Show fewer when additional cached posts exist. Article cards
open their canonical Substack URLs in a new tab.

Team contains Lucie Vanhollebeke and Blanche Marion, with black-and-white images,
color hover overlays, affiliations, disciplines, and LinkedIn links. Join Us
links to Bloom Lab on X, Instagram, and Substack. Preserve every section ID even
when a section is not represented in Navbar.


8. PROJECT AND UTILITY PAGES
----------------------------

The implemented project pages are light, long-form editorial routes with a
consistent Bloom visual language, a root back link/header, Platypi headings,
responsive content sections, and project-specific figures:

- BiologicalRelativity.tsx — "Biological Relativity: Modeling Aging With
  Spacetime"; uses aging, epigenetic modification, manifold, comparison-table,
  and event-photo assets.
- Soma.tsx — "Soma: Mapping the Hidden Networks Behind Personal Health"; uses
  soma_figure.jpeg.
- ReVamp.tsx — "ReVamp: Reading and Reversing Aging Through Blood"; uses the two
  ReVamp figures.
- SeneReveal.tsx — "SeneReveal: Teaching AI to Outsmart Cellular Aging"; uses
  three SeneReveal figures.
- 3bodies.tsx (component name Bodies) — "3Bodies: Modeling Aging Across
  Interconnected Physiological Systems"; uses three 3bodies figures.

ComingSoon.tsx is the BioResilience placeholder with a back link and primary
action. NotFound.tsx is the client-side 404 with a link to the root.


9. LEGACY NETWORK COMPONENT
---------------------------

src/pages/NetworkScrollSection.tsx remains in the repository but is not imported
or rendered by Index or MainLanding. It contains the former radial network/flower
hero and mount-driven path animations. Treat it as legacy code; do not restore
it to the homepage unless explicitly requested. The current question-field and
dot-to-molecule sequence replaces it.


10. COLOR, TYPOGRAPHY, AND MOTION SYSTEM
----------------------------------------

The site uses a restrained light theme. src/index.css defines HSL design tokens
for page surfaces, text, controls, borders, focus rings, sidebar components, and
the Bloom palette. tailwind.config.ts exposes:

  bloom-cyan           #73E8FF
  bloom-sky            #2BA4E0
  bloom-deep           #0E74D6
  bloom-violet         #7050FF
  bloom-dark           dark neutral
  bloom-textSecondary  secondary dark neutral

Deep blue is used for primary actions and links; cyan and sky blue support dots,
borders, and lighter accents; violet is used for selective emphasis, discipline
chips, and hover/focus treatments. Backgrounds are light blue-gray neutrals,
cards are white/translucent, and body text is dark. Avoid off-palette chromatic
colors unless explicitly requested; opacity variants and neutral colors are
normal parts of the design.

Satoshi is the global sans-serif family and is loaded locally from public/fonts.
Platypi Light is also loaded locally and exposed through .font-platypi for
editorial headings. index.css defines text-hero, text-section-header, and
text-body-large utilities. Global smooth scrolling applies only when the user
does not request reduced motion.

12. IMPLEMENTATION GUIDANCE
---------------------------

- Preserve React, TypeScript, Vite, React Router, Tailwind, and Framer Motion.
- Preserve the sticky 320vh intro and its direct scroll-progress mapping.
- Keep Index, IntroPage, and Navbar synchronized through introRef.
- Account for the post-entry scroll clamp when changing the 0.78 reveal point.
- Keep the navbar fixed outside document flow and preserve its accessibility
  state while hidden.
- Preserve responsive input support and prefers-reduced-motion behavior.
- Preserve homepage section IDs and GitHub Pages redirect handling.
- Keep project card paths synchronized with App.tsx routes.
- Treat NetworkScrollSection as unused legacy code.
- Prefer global tokens over new hardcoded colors.
- Avoid broad refactors of unused shadcn/ui scaffolding.
- Remember that production builds attempt a network-backed Substack refresh.
- Run npm run build after implementation and lint when proportionate.
- Do not deploy or publish unless explicitly asked.
